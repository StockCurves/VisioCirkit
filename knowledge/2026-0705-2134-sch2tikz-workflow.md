# sch2tikz 工作流程架構解析 (Workflow Architecture)

這份文件梳理了目前 `/sch2tikz` 技能將手繪/上傳電路圖轉換為精準 TikZ 程式碼的標準處理流程。整個系統採用了「**LLM 負責邏輯拓撲、程式碼負責絕對物理座標與驗證**」的混合式架構。

---

## 處理流程全貌 (Pipeline Stages)

### 1. 影像保存與前置處理 (Code)
- **執行方式**: 自動化腳本
- **任務**: 接收使用者的電路圖，將原始上傳影像備份儲存至 `sch2tikz-out/` 目錄，作為所有後續比對與驗證的基礎 (Ground Truth)。

### 2. 拓撲結構解析 (LLM)
- **執行方式**: 大型語言模型 (視覺分析)
- **任務**: 辨識電路圖中的元件種類、端點、迴路與走線關係。在這階段，LLM 只需要決定**「相對位置」**（例如：R17 在 M7 的左方、且與 C11 連接），不須精確計算小數點後的絕對防撞座標。

### 3. 特殊元件接腳偏移查詢 (Code)
- **執行方式**: `lookup_pin_offset.py` 腳本
- **任務**: 針對多接腳元件（如 OP-AMP、邏輯閘、電晶體），自動查表獲取相對於元件中心的接腳絕對偏移量（例如：NMOS 的 Gate 是 `dx = -0.98`）。這能輔助 LLM 在後續接線時絕對精準命中端點。

### 4. 草擬 TikZ 程式碼 (LLM)
- **執行方式**: 大型語言模型 (程式碼生成)
- **任務**: LLM 依據自己解析出的拓撲順序，產出第一版 `.tikz` 原始碼草稿，這份草稿的核心價值在於**建立正確的電路連線拓撲關係**。

### 5. 自動化拓撲網格拉伸 (Code)
- **執行方式**: `align_topology.py` 腳本
- **任務**: 這是解決 LLM 空間佈局擠壓與重疊問題的核心演算法。它會把 LLM 畫出來的狹小網格以數學方式均勻往外推撐 (Orthogonal Grid Relaxation)，強制各元件間保持符合 Bounding Box 標準的安全間距（如 1.0cm 以上），同時保持接腳的內部偏移量不變。

### 6. 編譯與渲染驗證 (Code)
- **執行方式**: `verify_tikz.py` 腳本
- **任務**: 使用本機的 LaTeX 環境（如 `pdflatex` + `dvisvgm`）或雲端的 QuickLaTeX API，將 TikZ 程式碼即時編譯並轉換為所見即所得的 SVG 向量圖。

## 品質保證機制 (QA Checks)

在草稿完成並渲染後，系統會透過嚴格的自動化程式碼檢查 (QA) 來確保輸出品的穩定度：

### QA 階段一：編輯器相容性檢查 (Code)
- **執行腳本**: `lint_editor_compat.py`
- **負責檢查**: 確保生成的 TikZ 語法完全符合 VisioCirkit 視覺化編輯器 (Frontend) 的解析引擎限制。
  - **核心檢查項目**：
    - 是否完全使用**絕對座標**（嚴禁使用相對座標 `++(1,0)` 或 `+(0,2)`）。
    - 接線點與節點是否使用標準的 `\node[circ]`。
    - I/O 端點是否使用 `osquarepole` 方框符號。
    - 是否錯誤使用不支援的複雜繪圖標籤（如 `[dashed]`, `[->]`）。

### QA 階段二：幾何防撞檢查 (Code)
- **執行腳本**: `lint_geometry_overlap.py`
- **負責檢查**: 解析 TikZ 並為每一個元件與標籤建立虛擬的 Bounding Box，進行嚴密的二維物理防撞測試。
  - **核心檢查項目**：
    - **元件實體重疊**：不同元件的主體不可交疊（例如電阻穿過電容）。
    - **文字標籤碰撞**：元件標示字樣 (Label) 是否和相鄰的元件外殼、導線或其它文字重疊。

## 結論與設計哲學
目前的 `/sch2tikz` 技能架構極大化了 AI 與傳統演算法的各自優勢。**LLM 不擅長精確計算空間距離，因此系統將空間距離計算、網格避障拉伸、編輯器相容性 Lint 等全數交接給穩定的 Python 程式執行；LLM 只需要發揮它最卓越的「視覺拓撲理解」與「語意翻譯能力」即可。**
